# SIS — Novonordisk Supply Chain (chore/remake)

Laravel 10 + Inertia 2 + **Svelte 5 (runes)** + **Metronic 9 (Tailwind 4, built from source)**. This file is the source of truth for a fresh session — read it first.

## Architecture
- **Decoupled JSON API + thin Inertia shell.** Controllers return the envelope `{ status, message, data }` (paginated `data = { data, meta, links }`); pages are Svelte and fetch client-side via the shared API client (NOT `Inertia::render` for data — web routes only render page shells, and they do it through `App\Http\Controllers\Web\*`, never inline in `routes/web.php`).
- Query contract (spatie/query-builder): `filter[field]`, `filter[search]`, `sort=field|-field`, `include=rel`, `per_page`, `page`.
- **No soft deletes, no archive.** `destroy` is a real delete; there are no restore/force-delete routes, no `deleted_at`, no `filter[trashed]`. Don't reintroduce them — and never add `Rule::unique(...)->whereNull('deleted_at')`, which is what broke every create/update the moment the column went.
- Auth: custom Sanctum-session + Azure SSO, approval gate via **`App\States\User\UserStatus`** (spatie/model-states): `pending` → `verified`|`approved`|`rejected`; `verified` → `approved`|`rejected`; `approved` → `rejected`; `rejected` → `approved` (nothing ever returns to `pending`). **Only `approved` may sign in** — gate on `$user->canLogin()`, never on the raw status. Azure SSO self-signup lands on `verified` (it proves identity, not admission); an admin-created user starts `approved` (creating it *is* the approval). Transitions are `POST users/{user}/{approve,reject,verify}`, each permission-gated; a disallowed transition is a 422, not a 500. Frontend labels/variants live in `lib/user.js`. Single upload route `POST /api/v1/admin/uploads` → forms submit only the returned media `id`. **Everything lives under the `admin` prefix** — only admins can reach this system — including auth (`/api/v1/admin/auth/*`), which stays *outside* `verify.auth` or you could never log in.
- **Sessions = Laravel's table in our shape.** `SESSION_DRIVER=database`; `App\Services\Sessions\SessionHandler` extends Laravel's and translates on the way in/out — `id` is a ULID (PHP's session id lives in `session_id`), `last_activity` is a datetime (Laravel writes unix seconds), plus `created_at`/`updated_at`. Registered over the `database` driver in `AppServiceProvider::useOurSessionTable()`. **`session_id` is the cookie value — a credential, never exposed**: it is in the model's `$hidden` and absent from `SessionData`; routes bind on the ULID. **Sessions are NOT audited** — the table already records who was signed in from where, and a session is written on *every request*, so an observer would add a row per page view. Deleting a row IS the logout. **`user_id` MUST stay nullable** — Laravel writes a session for guests too (the login page needs one for its CSRF token); NOT NULL makes the insert fail, the handler swallows it, and *nobody can log in*. A session is INSERTed on first contact and UPDATEd every request after; login calls `regenerate(true)` so the pre-login guest row is destroyed rather than orphaned. Expired rows: Laravel's `gc()` only fires on a `session.lottery` roll (2% of requests), so `Session` is `Prunable` and `model:prune` runs daily; reads go through `scopeActive()`/`scopeExpired()` rather than trusting the table. **Sessions are read per-user only** — one `SessionsController` (`GET sessions/{user}`, `DELETE sessions/{session}`), no app-wide list; plus `POST users/{user}/logout-devices`, which iterates because a builder `->delete()` fires no events.
- **Uploads = our own `App\Models\Media`** (spatie/laravel-medialibrary was removed — we used ~5% of it and fought the rest). `config/uploads.php`; `UploadService` is the only way files enter/move/leave. Two stages: `quarantine` disk → `ScanUpload` job (`FILE_SCANNER=null|clamav`, state `pending→clean|infected|failed`) → `public` disk. **Storage is flat**: every file is `uploads/{ULID}.{ext}` — the owner + collection live in the DB only (`model_type`/`model_id` nullable, `collection_name`), so attach/detach are pure DB writes and a file never moves. `media.name` = the real filename for display, `file_name` = the generated unique one. A file belongs to one model at a time; attaching an owned file copies it. `HasMedia` trait (`App\Traits\Uploads`) gives `media()`/`getMedia()`/`getFirstMediaUrl()`/`singleFileCollections()`.
- **Pruning is `Prunable` + `model:prune` (daily), never a bespoke command.** `Session` prunes expired rows and `Notification` is `MassPrunable`. **`Media` is deliberately NOT prunable** — it used to sweep never-attached uploads after 30 days, which is unsafe now that editor-inserted images are free media by design: they live in a page's HTML but are owned by nothing, so the sweep would eventually delete a file a live page still renders. Nothing deletes a file automatically; `DELETE media/{media}` (`media.destroy`, free media only — an attached one is a 422) is the single exit, surfaced as a Delete action on the Media page. The library accumulates, and that is the intended trade.
- **Content images are free media, not a collection.** A content module owns exactly one `thumbnail` (plus `files` on Album). Images the editor uploads are inserted by URL and never attached to anything — there is no `images` array on any DTO, no `IMAGES_COLLECTION`, and no content-scanning. `UploadService::sync()` survives for Album's ordered `files` gallery only.
- **Activity log** (spatie/activitylog): written by observers only, never by hand. Every observer extends `App\Observers\BaseObserver` (one class, both modes) and is registered in `AppServiceProvider`. **Pivot changes log against their parent** (granting a permission to an ApiKey is an `attached` activity on the ApiKey) — a pivot observer opts in by overriding `isPivot()` to `true` and implementing `parent()`/`related()`; everything else logs its own model's lifecycle. Causer = User *or* ApiKey via `CauserResolver` in `AppServiceProvider` (honour its `$subject` arg — an explicit `causedBy()` must win). Secrets are stripped by `neverLog()` (global backstop) + `ignored()` (per-model noise). **A delete only keeps what `loggedOnDelete()` names** — the record itself is gone, so name the columns worth keeping; `neverLog()`/`ignored()` still win over it. Read-only `GET /api/v1/admin/activities`; note `filter[search]` only covers `description`/`event`/`log_name`, and `description` holds just the event slug — so a deleted record is findable by `subject_id`, not by name; polymorphic columns are exposed as `App\Enums\MorphType` aliases (`api_key`), never class names. The UI builds messages from `(log_name, event)` — see `lib/activity.js`; `description` is the stored English fallback.
- **The admin UI itself is English-only and hardcoded.** There is no `$t()`, no `lib/i18n`, no `i18n` Inertia prop, no locale switch, no RTL: `<html dir="ltr" lang="en">` is fixed in `app.blade.php`, and nothing calls `App::setLocale()`. Write admin UI strings as literals in the component. `HandleInertiaRequests` shares only `auth` + `media` (upload rules). Activity-log wording lives in `lib/activity.js` (`ACTIVITY_MESSAGES`/`EVENT_LABELS`/`LOG_NAME_LABELS`/`SUBJECT_TYPE_LABELS`) — not in `lang/`.
- **Localisation is a managed catalogue, not a UI layer.** `lang/` holds 9 locales (`en ar fr es de it pt ru hi`), each with a full `validation.php` (Laravel's own server-side messages, e.g. `__('validation.date')` in `ActivitiesController`) plus a `common.php` the admin edits. **Translated strings live in the PHP files, never in the database** — `translation_keys` is a read-only key registry (`group` + dotted `key`, seeded from `config/translations.php`), and the Translations page paginates *that* while reading each value out of `lang/{code}/{group}.php`. `App\Services\Translations\TranslationService` is the only thing that touches those files: `put()` is parse → verify → replace under a sidecar `flock` (every registered key must survive the write, missing ones are filled with `''`), then a temp-file `rename()` and `opcache_invalidate()` — **that OPcache call is the whole cache story; Laravel has no lang cache and this app has no `Cache::` usage, so never add a `cache:clear` here.** A `Language` row owns its folder via `LanguageObserver`: create makes it, a `code` change renames it, and **delete deliberately leaves it on disk** (the translations are source and outlive the row). Exactly one `is_default`, enforced by a builder update in `saved()`. `@lang('common.save')` resolves against these files. **`lang/*/common.php` is committed, not gitignored** — keys are translated once by devs when they're introduced and rarely touched after, so those files are dev-authored source like `validation.php` and flow repo → deploy.
- **DB-backed translations were considered and rejected — don't reopen it without the trigger below.** Files win here because `@lang()`/`__()` read them natively: a DB translator needs a loader override *and* a cache (every rendered string would otherwise be a query), and this app has no caching layer to put it in. The costs are already paid (lock, atomic rename, OPcache). **The one thing that flips the decision is a second app server** — file writes land on one node only, so the day this runs behind a load balancer or in more than one container, it must move to the DB. That swap is contained to `TranslationService::load()`/`put()`; nothing else touches the files. Secondary limit: you cannot sort or filter by translated *value* in SQL (hence `value` is absent from `allowedSorts`), so a "missing translations" filter costs a PHP-side scan over the whole registry rather than a `WHERE`.

## Frontend layout — `resources/` is TWO apps, split at the top level
```
resources/
├── admin/   css/{app,brand}.css · js/{app.js,bootstrap.js,Pages,components,layouts,lib}
│            views/app.blade.php · metronic/ (the licensed theme source — gitignored, see below)
└── site/    css/{site,forms}.css · js/{site.js,components,lib} · views/{layout,forms}
```
- **The admin is the Inertia+Svelte+Metronic app. The site is the public website end users visit.** Nothing under `site/` may import from `admin/`, or the whole Metronic theme lands on a public page. The two have no shared module: the form renderer under `site/js/components/forms` is site-only, and the admin builder keeps its own copies of the two helpers it needs (`admin/js/lib/forms/{values,i18n}.js`) rather than reaching across.
- **Aliases:** `@` → `resources/admin/js` (so every existing admin import is untouched), `@site` → `resources/site/js`. An `@site/` import inside `resources/admin` is a boundary violation you can grep for.
- **Separate builds, separate manifests.** `npm run build` = `build:admin` then `build:site`; each is `vite build --mode {admin,site}` and writes to `public/build/{admin,site}`. A Vite build emits exactly one `manifest.json`, so the two cannot share a directory — hence the second argument in `@vite([...], 'build/admin')` / `@vite([...], 'build/site')`. A bare `vite build` with no `--mode` throws rather than silently half-building. `npm run dev` still serves BOTH from one server (Laravel keys hot mode off a single `public/hot` and ignores the build directory while it exists, so two dev servers cannot coexist).
- **Blade is namespaced `admin::` / `site::`** (`AppServiceProvider::registerViewNamespaces()`, both paths also in `config/view.php`). Inertia's `$rootView` is `admin::app`; the public form pages are `site::forms.*`. Use the prefix in our own code so a name that exists on both sides can never resolve to the wrong half.
- **Tailwind: both stylesheets use `@import 'tailwindcss' source(none)` + explicit `@source`.** v4's automatic source detection scans the WHOLE project and ignores `@source`, so without this the public page compiled every utility class found in `resources/admin` (site CSS was 37 kB; it is 11 kB scoped). Each side scans `../js/**/*.{svelte,js}` **and `../views/**/*.blade.php`** — the Blade shell's `<body>` class list is Tailwind utilities too, and dropping that glob strips the demo1 layout off the page.
- **`public/` mirrors the split:** `public/assets/admin/media/**` (Metronic's app/audio/avatars/brand-logos/flags/images) and `public/assets/site/` for the site's own static files. `public/build/` is Vite output, gitignored.
- Admin `lib/` — `api/{client,useIndex.svelte,useForm.svelte}`, `date`, `format`, `permissions`, `upload`, `activity`, `kt` (KTUI init), `menu` (sidebar config), `portal`, `toast`, `confirm`.
- Admin `components/{ui,form,data,media,feedback,layout,activity,charts,forms-builder}` — the deduplicated kit. Key: `IndexCard` (Metronic list card + fly-in create/edit swap), `DataTable` (sortable, skeleton, `kt-table`), `Filters` (config-driven drawer incl. `resource-select`), `Drawer`/`Modal` (Svelte-driven, portaled), `Dropdown` (portaled — avoids table overflow clipping), `Select` (async combobox = Select2 replacement), `PhoneInput` (intl-tel-input), `PasswordInput`, `DatePicker` (flatpickr), `MediaPicker`/`MediaLibraryModal`.
- Admin `layouts/{AdminLayout,AuthLayout}`, `Pages/Admin/**` (the `Admin/` segment is kept: it is the Inertia page key that `inertia('Admin/Users/Index')` passes) + `Pages/Admin/Auth/Login`.
- Note `components/form/` (admin input kit) and `site/js/components/forms/` (public renderer) are different things — before the split they sat side by side, distinguished only by a plural `s`.

## Conventions (match these)
- **Svelte 5 runes only** — `$props/$state/$derived/$effect`, callback props, snippets. No `export let`/`createEventDispatcher`/`on:`.
- Preserve the **Metronic demo1 look** (`kt-*` classes). Icons = **keenicons** (`ki-filled ki-*`).
- A module Index = `AdminLayout` + `IndexCard` with `toolbar`/`form`/`table` snippets; create/edit = **fly-in card swap**; view/filters/pivots = **right-side drawers**; row actions = portaled `Dropdown`.
- UI strings are plain English literals in the component — no translation layer, no lang files.
- **Phone inputs are normalized before validation.** A Data class with phone fields does `use App\Traits\Data\NormalizesPhones;` and names them in `phoneFields()` (defaults to `['phone']`). It hooks spatie/laravel-data's `prepareForPipeline()`, which runs BEFORE every pipe — so `Rule::unique` and `App\Rules\PhoneNumber` see E164 (`+213555123456`) and `+213 555 123 456` collides with an existing row instead of becoming a second account. `App\Services\Phone\PhoneFormatter::e164()` is the one formatter; it returns null for anything unparseable, and the trait falls back to the raw input so the validator reports it rather than `nullable` silently storing no phone.
- **Models are banner-sectioned** — every model in `app/Models/` has exactly four numbered sections, always all four in this order even when empty: `1. Attributes` (consts, `$guarded`, `$hidden`, `$appends`, `$casts`) → `2. Relationships` → `3. Accessors` (`get*Attribute()`) → `4. Methods` (everything else). Don't invent domain sections (Lifecycle, Permissions, …) — fold them into these. Format:
  ```php
      /* -----------------------------------------
       1. Attributes
      ------------------------------------------*/
  ```

## Gotchas (already solved — don't reintroduce)
- npm `@keenthemes/ktui` has **no `KTMenu`** → sidebar accordion/collapse are **Svelte-driven**, not `data-kt-menu`. KTUI (dropdowns/toggle/sticky/theme-switch) is init via `lib/kt.js` `initKt()` in `app.js` + `AdminLayout`.
- **Keenicons** must be imported in `app.js` (unlayered), NOT `@import`-ed into `app.css`, or Tailwind's `::before` reset wipes the glyphs.
- Don't put `kt-drawer` on the Svelte `Drawer` (its base CSS mis-positions it). `#app` needs `flex-grow:1;width:100%` (in `app.css`).
- KTUI widgets in client-rendered content (form panels, drawers) won't be re-init'd → use Svelte-native equivalents (`PasswordInput`, portaled `Dropdown`).
- **Flat media storage: never delete a media's *directory*, only its file.** The folder is shared by every model — a `deleteDirectory()` there wipes the whole app (this is what medialibrary's `DefaultFileRemover` and the old `ScanUpload` both did). Same reason `file_name` is a ULID with a unique index: two `invoice.pdf`s would otherwise be the same file.
- **Observers write the audit log; don't call `activity()` from controllers.** A model `updated` diff must ignore timestamps and skip empty diffs, or every password change writes a meaningless row.
- `useIndex` reads its `filter` **once at init** → a drawer reused across rows needs `setFilters()` on open (and `readUrl:false`, or it fights the page's query string).
- `Filters` passes `value=` (not `bind:value`) to `Select` and relies on `onchange`. A `resource-select` may take function props of the draft + `dependsOn` (see the causer filter in `Pages/Admin/Activities/Index.svelte`).
- PHP here is **8.1** — no constants in traits, no `readonly` classes.

## Build / run
`npm run build` (both bundles; or `npm run build:admin` / `npm run build:site`, or `npm run dev` for one server serving both) + `php artisan serve`. No jQuery. Detailed history + rationale: `~/.claude/plans/audit-the-app-folder-elegant-wreath.md` and the `remake-context-artifacts` memory.

**Metronic source is `resources/admin/metronic/`** (5,275 files, ~547 MB) — it belongs to the admin because nothing else may use it. Gitignored via `/resources/admin/metronic`; if you ever move it again, move that `.gitignore` line in the SAME commit or a licensed third-party theme lands in the repo. Only four imports reference it: three `@import '../metronic/src/css/…'` in `admin/css/app.css` and the keenicons `styles.bundle.css` in `admin/js/app.js`. It is deliberately NOT covered by the `@source` globs, so Tailwind never scans the theme's own 5,275 files. Because it sits inside `resources/`, a raw `grep -r resources/` in a shell walks all of them and effectively hangs — pass `--exclude-dir=metronic`. The Grep tool is unaffected (ripgrep honours `.gitignore`).
